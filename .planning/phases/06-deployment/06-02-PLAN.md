<threat_model>
## Security Threats

### T-01: BETTER_AUTH_SECRET entropy
- **Threat:** Weak or default BETTER_AUTH_SECRET allows session forgery
- **Mitigation:** Instructions specify `openssl rand -base64 32` which produces 256 bits of cryptographic randomness. Verification step checks the value is not the placeholder.
- **Severity:** CRITICAL if violated
- **Verification:** BETTER_AUTH_SECRET in Vercel is not "generate-a-random-32-char-secret"

### T-02: BETTER_AUTH_URL mismatch
- **Threat:** If BETTER_AUTH_URL doesn't match the actual deployment URL, auth callbacks break silently — login appears to work but sessions are invalid or redirect to wrong domain
- **Mitigation:** Verification step explicitly checks that BETTER_AUTH_URL matches the actual .vercel.app URL
- **Severity:** HIGH — auth completely broken if wrong
- **Verification:** Manual check during deployment verification

### T-03: Database connection string exposure
- **Threat:** DATABASE_URL visible in Vercel build logs or error pages
- **Mitigation:** Vercel masks environment variables in build logs by default. Next.js only exposes NEXT_PUBLIC_* to client. Error pages in production show generic messages.
- **Severity:** MEDIUM
- **Verification:** Check Vercel build logs do not contain the full connection string

### T-04: SSL not enforced on database connection
- **Threat:** Database traffic sent unencrypted
- **Mitigation:** Neon enforces SSL on all connections by default — there is no way to connect without SSL. The connection string includes `sslmode=require`.
- **Severity:** N/A — mitigated by default
</threat_model>

**Step 1: Push code to GitHub** (if not already there)
Ensure the honey_do2 repo is pushed to GitHub (public or private). Vercel needs a connected Git repo for auto-deploys.

**Step 2: Create Neon project**
1. Go to https://neon.tech and sign up (free tier)
2. Create a new project named "honey-do" (or similar)
3. Select the closest region to your users
4. Note: You do NOT need to copy connection strings manually — the Vercel integration handles this

**Step 3: Create Vercel project**
1. Go to https://vercel.com and sign up
2. Click "Import Project" and select the honey_do2 GitHub repo
3. Framework preset: Next.js (should auto-detect)
4. Do NOT deploy yet — configure env vars first

**Step 4: Connect Neon to Vercel**
1. In the Vercel dashboard, go to your project -> Storage -> Connect Database
2. Select Neon from the marketplace
3. Connect your Neon "honey-do" project
4. This automatically provisions these env vars in Vercel:
   - `DATABASE_URL` (pooled connection — used by the app at runtime)
   - `DATABASE_URL_UNPOOLED` (direct connection — used by drizzle-kit migrate in the build)

**Step 5: Set additional environment variables in Vercel**
In Vercel project -> Settings -> Environment Variables, add:

| Variable | Value | Environment |
|----------|-------|-------------|
| `BETTER_AUTH_SECRET` | Run `openssl rand -base64 32` and paste the output | Production, Preview, Development |
| `BETTER_AUTH_URL` | `https://[your-project-name].vercel.app` (check Vercel for exact URL) | Production |

CRITICAL: `BETTER_AUTH_URL` must be the EXACT URL Vercel assigns (e.g., `https://honey-do.vercel.app`). If this doesn't match, login will silently fail — users will appear to log in but sessions won't persist.

**Step 6: Deploy**
1. In Vercel, trigger a deploy (redeploy if it already ran, or push a commit to main)
2. Watch the build logs — you should see:
   - `drizzle-kit migrate` output (migrations applied to Neon)
   - `next build` output (app compiled)
3. Once deployed, note the URL (e.g., `https://honey-do.vercel.app`)
