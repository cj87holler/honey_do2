Create `.github/workflows/ci.yml`:

- Trigger on `pull_request` targeting `main`. Also trigger on `push` to `main` so the check has
  history on the default branch, which makes it selectable in branch-protection settings.
- Single `ci` job on `ubuntu-latest`.
- `actions/checkout` then `actions/setup-node` with `node-version: 22` (matching the local
  v22.11.0) and `cache: npm`.
- `npm ci` against the committed `package-lock.json`.
- Three separate steps so a failure names itself in the GitHub UI: `npm run typecheck`,
  `npm run lint -- --max-warnings 0`, `npx vitest run`.
- Add a `concurrency` group keyed on the ref with `cancel-in-progress: true` so superseded pushes
  do not queue up.

Two hard constraints from criterion 5, both load-bearing:
- **Do not run `npm run build`** — it is `drizzle-kit migrate && next build` and requires a live
  database.
- **Do not add a Postgres service container** — every DB-touching test mocks
  `vi.mock("@/lib/db", ...)`. Re-confirm this by grepping the test suite before relying on it.

Run the three commands locally in sequence exactly as the workflow will, to confirm the gate is
green before it ever reaches GitHub.
